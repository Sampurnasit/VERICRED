> **Document ID**: DOC-API-002

## 1. Standard Error Envelope Structure

VERICRED enforces a strict, predictable JSON error envelope across all backend API responses. This standard prevents client-side deserialization crashes and ensures consistent error logging.

```json
{
  "success": false,
  "error": {
    "code": "VC_INVALID_SIGNATURE",
    "message": "The cryptographic signature on this credential failed verification.",
    "details": null
  },
  "meta": {
    "timestamp": "2026-11-20T00:50:00.000Z",
    "requestId": "req-9876-5432-10fe-dcba"
  }
}
```

## 2. Standard HTTP Status Code Mapping

| Status Code | Semantics | Typical VERICRED Scenario |
| :--- | :--- | :--- |
| **`400 Bad Request`** | Malformed syntax or invalid parameter | Invalid CGPA ($> 10.0$), Zod schema failure |
| **`401 Unauthorized`** | Missing or invalid authentication token | Expired JWT, missing `access_token` cookie |
| **`403 Forbidden`** | Authenticated, but lacks required role | Student calling `/admin/approve`, Unapproved institution issuing |
| **`404 Not Found`** | Resource does not exist | Credential ID or presentation UUID not in DB |
| **`409 Conflict`** | Resource collision | Institutional short code or user email already taken |
| **`410 Gone`** | Resource intentionally expired | Ephemeral presentation exceeded 15-minute TTL |
| **`422 Unprocessable`**| Syntactically valid, but cryptographically invalid | Groth16 proof fails pairing equation, EdDSA signature broken |
| **`429 Too Many Req`**| Rate limit exceeded | Verifier scanning $> 60$ requests / minute |
| **`500 Internal Error`**| Uncaught system fault | Database connection drop, internal runtime panic |
| **`502 Bad Gateway`** | External upstream failure | Polygon Amoy RPC node timeout or connection refused |

## 3. Domain-Specific Error Code Directory

### 3.1 Authentication & User Management (`AUTH_*`)
- `AUTH_INVALID_CREDENTIALS`: Password or email mismatch.
- `AUTH_TOKEN_EXPIRED`: JWT access token expired.
- `AUTH_TOKEN_REVOKED`: Session invalidated via logout or refresh token rotation conflict.
- `AUTH_FORBIDDEN_ROLE`: Insufficient RBAC privileges.

### 3.2 Credential & Issuance Errors (`VC_*`)
- `VC_INVALID_SCHEMA`: Data payload violates W3C VC 2.0 schema requirements.
- `VC_INVALID_CGPA_RANGE`: Academic grade not within $[0.00, 10.00]$ range.
- `VC_INVALID_SIGNATURE`: EdDSA / BabyJubjub signature mathematically invalid.
- `VC_ALREADY_REVOKED`: Revocation attempted on a credential already marked revoked.
- `VC_NOT_AUTHORIZED_ISSUER`: Submitting key is not authorized in `InstitutionRegistry.sol`.

### 3.3 Zero-Knowledge Proof Errors (`ZK_*`)
- `ZK_PROOF_INVALID`: Groth16 pairing check failed ($e(A, B) \ne e(\alpha, \beta) \cdot \dots$).
- `ZK_WITNESS_GENERATION_FAILED`: Client inputs fail constraint satisfaction (e.g., $x < T$).
- `ZK_INVALID_PUBLIC_SIGNALS`: Public inputs altered or inconsistent with circuit definition.
- `ZK_VKEY_UNAVAILABLE`: Verification key artifact failed to load.

### 3.4 Blockchain & Settlement Errors (`BC_*`)
- `BC_RPC_TIMEOUT`: Polygon Amoy JSON-RPC failed to respond within $5\,\text{seconds}$.
- `BC_TX_REVERTED`: Smart contract transaction reverted (custom error thrown).
- `BC_NONCE_COLLISION`: Transaction submitted with stale nonce.
- `BC_INSUFFICIENT_GAS`: Relay wallet lacks POL testnet tokens.

## 4. Input Validation Error Format (Zod Integration)

When a request body fails Zod schema validation, the `details` array provides field-specific diagnostics:

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The submitted payload contains validation errors.",
    "details": [
      {
        "field": "cgpa",
        "message": "CGPA must be a decimal number between 0.00 and 10.00"
      },
      {
        "field": "graduationYear",
        "message": "Graduation year cannot be in the future past 2030"
      }
    ]
  },
  "meta": {
    "timestamp": "2026-11-20T00:50:00.000Z",
    "requestId": "req-1234-abcd"
  }
}
```

## 5. Security & Information Sanitization Rules

1. **No Stack Trace Leakage**: Stack traces (`err.stack`) must NEVER be transmitted to the client in production (`NODE_ENV === 'production'`).
2. **Database Masking**: PostgreSQL SQLSTATE errors (e.g., `23505 unique_violation`) must be caught and mapped to user-friendly messages rather than exposing raw table or column names.
3. **Correlation Tracking**: Every error response includes a unique `requestId` generated by the gateway middleware, enabling developers to correlate user complaints with structured server logs in Pino.
